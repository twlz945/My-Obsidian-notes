# 笔记格式规范

生成新笔记时遵循本文件。目标是"富笔记"：带 YAML 属性、结构清晰、与库内笔记双向链接。

## 默认模板

~~~markdown
---
title: 笔记标题
date: 2026-10-01
tags:
  - 主标签
  - 具体标签
aliases:
  - 别名或英文名
related:
  - "[[相关笔记]]"
---

# 笔记标题

一句话概述这篇笔记讲什么、解决什么问题。

## 核心要点

- 要点一
- 要点二

## 详细说明

按主题分小节展开。需要对比时用表格：

| 概念 | 说明 |
| ---- | ---- |
| A    | …… |
| B    | …… |

## 相关笔记

- [[相关笔记 A]]
- [[相关笔记 B]]

## 参考来源

- [来源标题](https://example.com)
~~~

## 属性（frontmatter）

- 使用 YAML，起始和结束都是独立的 `---` 行，放在文件最顶部。
- 常用字段：
  - `title`：笔记标题（与 H1 一致即可，可不填）。
  - `date`：创建日期，`YYYY-MM-DD`。
  - `tags`：标签列表，或 `tags: [a, b]`。
  - `aliases`：别名，便于用不同名字建立 `[[链接]]`。
  - `related`：相关笔记的 wikilink，**必须加引号**：`"[[X]]"`。
  - `source`：单一来源 URL；多个来源写在正文"参考来源"。
- 已存在的笔记若已有属性，编辑时保留原有键，不要重排或删除。
- 属性值里出现 `:`、`#`、`[`、`]`、`{`、`}` 时用引号包起来。

## 标签

- 用 `#标签`（正文内联）或 `tags:`（属性）表达。
- 标签内不能有空格；层级用 `/`，例如 `#编程/Python`。
- 中文标签允许。优先复用库中已有标签，保持中英一致（库中既有 `#编程` 也有 `#TCP`）。
- 每篇 1–3 个标签，避免堆砌。

## 链接（wikilink）

- 指向库内笔记用 `[[笔记名]]`；需要不同显示文字用 `[[笔记名|显示文字]]`。
- 指向标题用 `[[笔记名#标题]]`，指向块用 `[[笔记名#^block-id]]`。
- 指外部网址用普通 Markdown 链接 `[标题](https://...)`。
- 正文中**首次**提到某个已存在的库内笔记时建立链接，同一篇内不必重复链接。
- 只有确认目标笔记存在时才创建 wikilink。若有意留占位链接，需在交付说明里指出。

## 正文风格

- 语言与关键词一致：中文关键词写中文，英文关键词写英文，混合主题以主体语言为主。
- 先给概述，再分点，再展开；避免一上来就是长段落。
- 代码用围栏代码块并标注语言。
- 不写"本文由 AI 生成"之类的元信息，除非用户要求。
- 不编造版本号、API 名称、链接；不确定处标注 `> [!warning] 待确认：……`。
