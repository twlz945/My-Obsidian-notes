# 整理判定标准

执行阶段按本文件的规则做决定。所有动作都要能被审计结果支撑，不要凭感觉改动。

## 通用原则

- 改前先读原文件，保留作者的写法、语气和未知 frontmatter 键。
- 一次只做一类改动，便于复核与回滚。
- 拿不准就标注 `> [!warning] 待确认：……`，不要擅自下结论。
- 风险分级：低（格式、标签、补属性）、中（改链接、重命名）、高（跨目录移动、合并、删除）。高风险的每一项都要单独确认。

## 一、元数据与标签（低风险）

- **补 frontmatter**：库中多数笔记没有属性。给缺属性的笔记补最小集合：`title`、`date`、`tags`。`date` 用文件创建日期或今天，`title` 用文件名。
- **标签订口**：
  - 优先复用高频标签（审计 `metadata.tagCounts` 里 count 高的）。
  - 只出现一次的零散标签（`rareTags`）优先合并到语义相近的既有标签，例如把 `API开发`、`Web开发` 视情况并入 `后端开发` 或保留（若确为独立主题）。
  - 层级标签用 `/`，如 `编程/Python`；避免同时存在 `Python` 和 `编程/Python` 造成重复。
  - 每篇 1–3 个标签。
- **aliases**：英文名、缩写、常见别名放到 `aliases`，便于双链命中。
- YAML 中 wikilink 值必须加引号：`related: ["[[X]]"]`。
- 保留原有键，不重排顺序。

## 二、目录归档（中风险）

- **重命名「未命名」**：`untitled` 列表里的文件，读内容后拟一个准确标题（文件名即标题）。空文件先问用户是否需要，不要自行删除。
- **填充空/极短笔记**（`stubs`）：先判断是否为占位，是则补最少内容或询问；不要凭空扩写。
- **移动错放笔记**：按下面路由表移动；移动时优先用 Obsidian CLI 的链接感知移动，否则用 `move-note.ps1`（会同步更新双链）。
- 纯移动（文件名不变）通常不需要改链接——Obsidian 按文件名解析；同名冲突时除外。

### 目录路由表

| 主题 | 目标目录 |
| ---- | -------- |
| 编程语言、框架、设计模式 | `知识积累/编程/` |
| Godot | `知识积累/编程/Godot/` |
| 学习路线、教程、入门 | `知识积累/编程/教程/` |
| TCP/UDP/Socket/HTTP、Web 后端 | `知识积累/编程/网络/` |
| Markdown、Obsidian、双链 | `知识积累/编辑/` |
| ESP32、FreeRTOS、GPIO | `esp32/` 对应子目录 |
| Turing Complete、指令集、CPU 架构 | `turing complete/` 对应子目录 |
| 游戏开发方法、规划 | `游戏开发/规划/` |
| 具体项目 | `project/<项目名>/` |
| 日记、随笔 | `杂记/` 或 `杂记/日记/` |

优先放入已有目录；确需新建目录时先确认。

## 三、去重与合并（高风险，逐项确认）

判定信号（来自 `duplicates`）：

- `sameTitle`：不同目录下有同名文件。
- `titleOverlaps`：一个标题包含另一个（如 `Socket` 与 `Socket入门文档`）。

处理步骤：

1. 先读两篇全文，判断是**真重复**还是**主题相关但内容不同**。
   - 主题相关不等于重复。例如 `Socket` 与 `Socket入门文档` 可能是「概念」与「教程」，应保留两篇并互链，不要合并。
   - 真重复：大部分内容可互相覆盖。
2. 真重复时，选内容最全、结构最好的一篇作为主篇。
3. 把另一篇的**独有有效信息**并入主篇，保留来源与不确定标注。
4. 另一篇的去留由用户决定：
   - 保留为存根 → 改成一句话 + `[[主篇]]` 链接；
   - 移入回收站 → 用 Obsidian 回收站，不用文件系统删除；
   - 删除 → 仅在用户明确同意后。
5. 合并后更新所有指向旧标题的双链（用 `move-note.ps1` 重命名逻辑，或手动 `edit`）。

**绝不为了整齐而合并。宁可保留，不可丢信息。**

## 四、链接与索引（中风险）

- **失效双链**（`links.broken`）：逐个决定
  1. 指向已有等价笔记 → 改成正确目标（`edit`）；
  2. 目标应是独立主题 → 可创建该笔记（转用 `obsidian-keyword-notes` 技能）；
  3. 纯笔误 → 修正；
  4. 确实不需要 → 删除该链接，但需用户同意。
  不要一律删链。
- **孤儿 / 无出链笔记**（`links.orphans`、`noOutgoing`）：优先在相关笔记中补 1–2 个双向链接，或建索引页归拢。日常日记类孤儿可忽略。
- **索引 / MOC**（`filing.foldersWithoutIndex`）：只有当用户要求或目录确实缺导航时，才新建 `index.md` 或 `<文件夹名>目录.md`：
  - frontmatter：`title`、`tags`；
  - 正文用 wikilink 按子主题分组列出该目录笔记；
  - 不要罗列太多而无分组。

## 五、格式清理（低风险）

统一到 Obsidian 友好格式：

- frontmatter 放最顶部，`---` 单独成行；YAML 合法，wikilink 加引号。
- 每篇至多一个 H1（`#`），作为标题；正文从 `##` 开始。标题 `#` 后必须有一个空格。
- 代码块用围栏并标语言；围栏成对闭合。
- 连续空行最多一个；行尾不留空格；文件以单个换行结尾。
- 用 UTF-8 无 BOM 保存。
- 不改动表格与代码块内部的对齐和缩进。

## 复核清单

执行后重新审计，确认：

- `brokenCount` 没有上升；
- 目标问题项已从列表中消失；
- 没有产生新的同名冲突或空文件；
- 被移动/重命名笔记的入链仍然有效（可在 Obsidian 里查看反向链接）。
