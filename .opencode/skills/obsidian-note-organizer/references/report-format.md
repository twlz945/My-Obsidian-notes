# 审计报告格式

把 `vault-audit.ps1` 的 JSON 汇总成本格式给用户。目标是让用户一眼看懂问题、风险和建议，并据此批准。

## 报告模板

~~~markdown
# Obsidian 库整理审计报告

- 库：<vault>
- 时间：<scannedAt>
- 笔记总数：<noteCount>

## 结论速览

- 元数据：<n> 篇缺 frontmatter，<n> 篇无标签，<n> 个标签仅出现一次
- 归档：<n> 篇「未命名」、<n> 篇空笔记
- 重复：<n> 组同名笔记，<n> 组标题包含关系
- 链接：<n> 个失效双链，<n> 篇孤儿笔记，<n> 篇无出链
- 格式：多重 H1 <n> 篇、标题缺空格 <n> 篇、未闭合代码块 <n> 篇、缺结尾换行 <n> 篇

## 详细发现

### 1. 元数据与标签（风险：低）
- `path/to/note.md`：无 frontmatter → 建议补 title/tags/date
- 标签 `xxx` 仅出现一次 → 建议并入 `yyy`

### 2. 目录归档（风险：中）
- `杂记\日记\未命名.md`：「未命名」→ 建议重命名为 `<建议标题>`
- `知识积累\编程\未命名 1.md`：空笔记 → 建议先确认是否还需要

### 3. 去重与合并（风险：高）
- `A.md` 与 `B.md` 同名/高度重叠 → 建议以 `A.md` 为主合并，`B.md` 处理后需你决定

### 4. 链接与索引（风险：中）
- `JSON.md:237` 的 `[[HTTP]]` 无目标 → 建议改为 `[[TCP]]`/新建 `HTTP.md`/删除
- `知识积累\编程` 无索引页 → 建议新建 `index.md`

### 5. 格式清理（风险：低）
- 统一结尾换行、标题后空格、单一 H1 等

## 变更计划

| # | 文件 | 问题 | 建议动作 | 风险 | 需确认 |
| - | ---- | ---- | -------- | ---- | ------ |
| 1 | ... | ... | ... | 低/中/高 | 否/是 |

请告诉我批准哪些编号（可整体批准、或按类别批准）。
~~~

## 写作要点

- 用中文，路径用库内相对路径（反斜杠或斜杠均可，保持与用户系统一致）。
- 每个发现都要能追溯到审计 JSON 的具体字段，不要编造。
- 「变更计划」表必须逐条列出；高风险项一律标「需确认」。
- 审计列表被 `-MaxItems` 截断了要说「已列出前 N 条，共 M 条」，不要用截断数据下结论。
- 不要在这一步修改任何文件。
