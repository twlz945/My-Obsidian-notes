## 0. 术语表

| 术语 | 含义 |
| --- | --- |
| Tick | 模拟最小时间单位，默认 50ms（20 TPS），与 Minecraft 一致 |

## 1. 项目概述

### 1.1 一句话定位
> 把「格雷科技」那种**层层嵌套、化工纠缠、电压爬梯**的工业苦修，改造成一款**可以离线成长、自动化解痛**的放置/增量（Idle/Incremental）游戏。

### 1.2 目标玩家
- 喜欢 GregTech / Factorio / 异星工厂 / 增量游戏（Antimatter Dimensions、NGU、Kittens Game）的玩家；
- 能接受「先苦后爽」的节奏：前期手动点、手动搓，中后期靠自动化与并行爆发。

### 1.3 设计支柱（一切需求不得违背）

| # | 支柱 | 含义 |
| --- | --- | --- |
| P1 | **苦修 → 解痛** | 每个繁琐步骤先让玩家手动体验一次痛苦，再用机器/自动化把它消掉；自动化本身是奖励。 |
| P2 | **电压即进度** | 核心成长轴是电压等级（每级 ×4 功率），而非单纯的数字变大。升压是里程碑事件。 |
| P3 | **链条深度** | 高级产物必须有 10~30 步嵌套配方（矿石→化工→电路→机器→更高级机器），并产生需要处理的副产物。 |
| P4 | **放置友好** | 任何时候关掉游戏，回来都能看到增长；离线收益必须有，且不惩罚玩家。 |

### 1.4 从格雷科技保留 / 舍弃

**保留（作为玩法核心）**
- 电压等级体系与「超压炸机」风险；
- 矿石处理链（粉碎→洗净→离心/热离→纯碎→熔炼）与副产物；
- 化工链（硫酸/盐酸/硝酸/氯/氢氟酸、电解、离心、蒸馏塔）；
- 电路等级（真空管→电子管→集成电路→处理器→量子…）；
- 多方块结构（高炉、真空冷冻机、装配线、聚变堆…）；
- 电缆线损、机器维护（扳手/软锤）、污染；
- 手工合成需要工具（锤/锉/锯/扳手/螺丝刀）及工具耐久。

**舍弃 / 改写**
- 三维世界、方块挖掘、实体与战斗 → 抽象为「矿脉地图 + 钻机」；
- 逐方块搭多方块 → 抽象为「结构图 + 部件清单 + 一次性组装」；
- 配方需要 JEI 手动查表 → 内建 NEI 式配方浏览器；
- MC 原生物品体系与模组兼容 → 全部自定义数据表。

## 2. 玩法概览

### 2.1 核心循环

```
勘探矿脉 → 采矿 → 手动加工（体验痛苦）
      ↓                              ↑
解锁机器 → 造发电机 → 供电 → 机器自动加工
      ↓                              ↑
副产物堵塞/线损/污染 → 需要化工与物流 → 造更大的机器
      ↓
升压（LV→MV→HV→…）→ 开新链 → 多方块 → 聚变 → 世界线重载
```

### 2.2 阶段路线（Tier 表）

| 阶段 | 名称 | 特征 | 目标时长（现实时间，含放置） |
| --- | --- | --- | --- |
| T0 | 石器/手工 | 点击采矿、手搓工具、石炉 | 0–15 min |
| T1 | 蒸汽时代 | 蒸汽锅炉、青铜机器、焦炉、原始高炉 | 15 min – 1.5 h |
| T2 | LV | 第一台发电机、电缆、电解机、粉碎机 | 1.5 – 3 h |
| T3 | MV | 离心机、化学反应釜、蒸馏塔、矿物处理全链 | 3 – 5 h |
| T4 | HV | 电路自动化、洁净室、装配机、线损优化 | 5 – 8 h |
| T5 | EV/IV | 多方块并行、真空冷冻机、钛/钨处理 | 8 – 14 h |
| T6 | LuV+ | 聚变、量子处理器、终极目标（星门/世界线重载） | 14 h+ / 无限 |

> **AC-1**：一名熟悉同类游戏的玩家，首个完整周目（到世界线重载解锁）应在 **8–15 小时**内可达成；纯放置（每天上线 3 次）不超过 7 天。

## 3. 功能需求（FR）

### FR-1 时间与模拟核心

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-1.1 | 固定步长模拟：1 tick = 50ms，20 TPS；主循环与渲染解耦，掉帧不影响模拟进度 | M |
| FR-1.2 | 模拟核心为纯函数式（状态进 → 状态出），不依赖 DOM，可在无界面环境下跑 | M |
| FR-1.3 | 支持时间加速/多步结算：单帧最多补算 N tick（默认 4，可配置），保证长时间挂机后不卡死 | M |
| FR-1.4 | 页面切到后台时用 `requestAnimationFrame` 降频 + 时间戳补偿，不丢失进度 | M |
| FR-1.5 | 游戏速度倍率可调（1x / 2x / 5x），调试模式提供 100x | C |

### FR-2 资源系统

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-2.1 | 三类资源：**物品**（整数计数）、**流体**（mB 整数计数）、**能量**（EU，大数） | M |
| FR-2.2 | 物品/流体携带**标签（tags）**（如 `dust`、`ingot`、`acid`、`circuit`），配方与物流可按标签匹配 | S |
| FR-2.3 | 物品支持**元数据/变体**（同种物品不同等级，如电路等级 1–8） | M |
| FR-2.4 | 所有资源有分类（材料/零件/流体/电路/机器/工具/杂项），UI 按分类折叠 | M |
| FR-2.5 | 资源列表可搜索、可排序、可收藏（置顶常用资源） | S |
| FR-2.6 | 数值采用**尾数+指数大数**表示（BigNum），支持到 1e308 以上不溢出、不失精度 | M |

### FR-3 配方与合成

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-3.1 | 配方为**数据驱动**：输入（物品/流体/能量）、输出（含概率产出与副产物）、时长（tick）、所需电压等级、所需机器类型、可选工具 | M |
| FR-3.2 | 支持**概率输出**（如粉碎副产 10%）与**多产物输出** | M |
| FR-3.3 | 支持**循环配方**（如硫酸→…→硫酸再生），并保证模拟不产生正反馈无限资源（需在平衡阶段验证） | S |
| FR-3.4 | 手工合成台：无限输入槽，符合配方即可合成，无需电力但耗时且可能消耗工具耐久 | M |
| FR-3.5 | **批次合成**：一次合成 N 份（1/10/100/最大），并显示预计耗时 | M |

| ID | 需求 | 优先级 |

## 5. 数值框架（初版公式，全部可调）

```
功率(P) = 电压等级值
超频(经典)：每升 1 档 → 时长 ÷ 2, EU/t × 4   (单次总能耗 × 2)
超频(完美)：每升 1 档 → 时长 ÷ 4, EU/t × 4   (单次总能耗不变)
机器并行度 = 结构/插件决定，单机上限 1，多方块 4^n
线损 = 基础(1%/格) → 超导(0%)
矿物处理产出倍率：直接 1× / 机械线 1.5× / 全化学线 2.5–3×
成本曲线：C(tier n) ≈ C(LV) × 4^(n-1)
离线收益：min(离线秒数, 上限) × 在线效率 × 全局倍率，分段模拟
转生货币：研究数据 = f(总 EU 产出, 最高电压, 达成的多方块数)
```

## 6. 非功能需求（NFR）

## 7. 技术选型建议（**待确认**）

| 项 | 建议 | 理由 |
| --- | --- | --- |
| 形态 | 单页 Web 游戏（HTML + CSS + TS） | 零安装、随时打开、方便迭代与分享 |
| 构建 | Vite | 快、配置少 |
| UI 层 | 原生 DOM + 轻量自研组件（或 Preact/Solid） | 放置游戏以表格/列表/面板为主，无需重型框架 |
| 渲染 | DOM/CSS 为主；仅在需要时用 Canvas 画物流/矿脉图 | 简单、可访问 |
| 状态 | 自研单例 Store + 订阅刷新（或 Zustand 风格极简实现） | 避免过度设计 |
| 大数 | 自研 BigNum（mantissa/exponent）或 tiny 大数库 | 后期数值必然爆炸 |
| 存档 | localStorage（+ 导出文本），后续可换 IndexedDB | 简单可靠 |
| 测试 | Vitest（含 headless 平衡模拟） | 数值密集项目必须有测试 |
| 运行环境 | 需要 Node.js + pnpm/npm（仅构建期）；成品为纯静态文件 | 便于部署到任何静态托管 |

## 9. 验收标准（总）

- **AC-1** 完整周目 8–15 小时（见 2.2）。
- **AC-2** 任何一个「机器停产」状态，UI 都能在一层界面内说明原因与缺失资源。
- **AC-3** 1000 台机器运行时，模拟 + 渲染保持 60 FPS（或至少 30 FPS 不卡顿）。
- **AC-4** 关闭页面 8 小时后再打开，收益与「保持在线 8 小时」的差距 ≤ 5%。
- **AC-5** 无外部资源依赖（无字体/图片/音效 CDN），断开网络可完整游玩。
- **AC-6** 核心逻辑单测通过率 100%，关键公式（超频/线损/离线/大数）有边界用例。
- **AC-7** 数据表校验脚本能发现：无来源资源、循环依赖、无解配方。
- **AC-8** 存档可跨版本迁移，旧档导入不报错。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 配方数量爆炸，制作成本失控 | 工期 | 数据驱动 + 自动生成工具（如按材料模板批量生成锭/粉/板/齿轮配方） |

| 后期 UI 信息过载 | 体验 | 分类折叠 + 搜索 + 收藏 + 卡点提示优先 |
| 前期 15 分钟太枯燥导致流失 | 留存 | 手动阶段加入点击反馈、快速里程碑、首次自动化在 15 分钟内实现 |
| 存档兼容性 | 数据丢失 | 版本号 + 迁移函数 + 导出备份 + 损坏回退 |

## 12. 待确认问题

1. **交付形态**：确认做「单页 Web 游戏」（推荐），还是需要其他平台（桌面端 / 命令行 / 其他语言）？
2. **视觉风格**：像素风（偏 MC/GT 原味）还是简洁现代工业风（更省美术成本）？
3. **语言**：首版只做简体中文，还是中文 + 英文双语同做？
4. **首版范围**：先做 **M1 可玩原型**（推荐，快速验证手感），还是直接朝 M6 完整版推进？
5. **数值强度**：偏「舒适放置」（自动化收益大、上手快）还是偏「格雷原味苦修」（链长、卡点多、成就感更强）？
6. **是否接受需要 Node.js 环境的构建流程**（需要本地跑 `npm install` 才能构建/运行），还是要求**双击一个 HTML 文件即可运行**（零依赖、无需构建）？
