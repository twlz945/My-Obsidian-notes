# 游戏开发学习规划

已经掌握常用编程语言的基础语法之后，缺的不是「游戏开发知识」，而是**把一个项目真正做完的工程能力**。本笔记给出两条路线的阶段化学习方案，原则只有一个：**只学支撑下一个可运行产物所需的知识**。

## 核心结论

1. **不要先学完再做游戏，而是做一个小的完整游戏。** 以项目驱动，just-in-time 学习。
2. 语法 → 成品之间的真实缺口是四项：把项目做完的经验、数据驱动架构、数值与模拟、序列化与版本迁移。
3. **先做放置游戏（路线 A），后做 Godot（路线 B）。** A 的需求已完整、可交付，且其技能与 B 高度重叠。
4. 学习计划应该**挂靠在自己的里程碑上**（M1→M7），而不是按教材章节走。

## 两条路线对比

|       | 路线 A：Web 放置游戏                                              | 路线 B：Godot 模拟建造           |
| ----- | ---------------------------------------------------------- | ------------------------- |
| 对应项目  | [[project/greg-like game/REQUIREMENTS.md\|格雷风格放置游戏]]       | [[游戏开发/规划/我的想法.md\|我的想法]] |
| 技术栈   | [[TypeScript]] + DOM/CSS + [[../../知识积累/编程/前端/Vite\|Vite]] | Godot（GDScript / C#）      |
| 核心难点  | 模拟核心、数据驱动、大数、存档迁移、UI 状态                                    | 引擎心智、实时循环、节点/场景、2D 数学     |
| 图形学要求 | 几乎为零                                                       | 中等（2D 为主，仍无需自研渲染）         |
| 现状    | 需求已到 v0.1，有 M0–M7                                          | 仅概念与层级定义                  |
| 建议顺序  | **先做**                                                     | 之后                        |

## 路线 A：Web 放置游戏（TypeScript）

### 阶段路线

| 阶段       | 学什么                                        | 产出（对应里程碑）                    | 预估      |
| -------- | ------------------------------------------ | ---------------------------- | ------- |
| 0 起步     | TypeScript strict、ESM、pnpm/npm、Vite、Git 基础 | 空项目跑通，`npm run dev` 出画面      | 1 周     |
| 1 模拟核心   | 固定步长循环、纯函数状态、BigNum（尾数+指数）、Vitest          | **M1**：手动采矿 + 石炉 + 存档 + 离线结算 | 2–4 周   |
| 2 UI 与状态 | 单向数据流、订阅刷新、虚拟滚动、`requestAnimationFrame` 降频 | **M2**：电力、线损、机器面板、NEI 配方浏览器  | 3–5 周   |
| 3 系统复杂度  | 数据表校验、化工链、副产物、物流网络、自动合成、科技树                | **M3 + M4**                  | 1.5–2 月 |
| 4 平衡与工具  | headless 模拟脚本、参数外置、配方自动生成                  | **M5 + M6**                  | 1–2 月   |
| 5 发布     | 静态托管、性能剖析、可达性、新手引导                         | **M7**                       | 2–3 周   |

> [!important] 两条分界线
> 阶段 1 之前**不要碰 UI**；阶段 4 之前**不要做平衡**。FR-20.1 调试面板要尽早做，它是后面所有阶段的眼睛。

### 准备就绪自测（都能在 1 天内做出原型即过关）

- [x] 写出一个不会因掉帧而漂移的固定步长循环
- [ ] 用 JSON 描述一条配方，换文件不改代码即可生效
- [ ] 存档 → 刷新 → 状态完全一致

## 路线 B：Godot 模拟建造

### 额外要补的三块

1. **引擎心智**：节点/场景树、`_process` 与 `_physics_process` 的区别、信号（≈事件总线）、Resource（≈数据驱动的载体）。参见 [[知识积累/编程/Godot/节点与场景.md|节点与场景]]。
2. **实时循环**：与放置游戏的 tick 不同，需理解帧率、插值、对象池。
3. **2D 数学**：向量、点积、坐标变换、A*。**只学这些**，不要一上来碰 OpenGL / 渲染管线 / 着色器。

### 阶段路线

| 阶段 | 学什么 | 产出 |
| --- | --- | --- |
| 0 引擎入门 | 场景与节点、输入、信号、Resource | 一个可移动的方块 + 一个场景切换 |
| 1 小游戏闭环 | 状态机、碰撞、计时器 | 完成 2 个经典小游戏（如贪吃蛇、打砖块） |
| 2 模拟层 | 与路线 A 相同的纯逻辑层（可复用其设计） | 机器/模块/网络的数据模型 + 单测 |
| 3 垂直切片 | 存档序列化、UI、烘焙 | 你的设计里的**最小闭环**：一台机器跑通一条配方 |
| 4 内容与打磨 | 性能、美术管线、发布 | 可发布的小作品 |

## 通用工程能力（两条路线共用）

| 能力 | 为什么必须 | 复用来源 |
| --- | --- | --- |
| Git（分支/提交/回滚） | 敢改代码的前提 | 通用 |
| 单元测试 | 数值密集项目的命脉 | [[../../知识积累/编程/教程/python/Python进阶阶段学习规划表\|Python 进阶学习规划表]] 3.2 节 |
| 静态类型 / lint | 大项目可维护 | 同上 3.3 节 |
| 数据驱动设计 | 后期改得动 | A 的 NFR-5、B 的组件系统 |
| 序列化与版本迁移 | 存档不能坏 | A 的 FR-15.2、AC-8 |
| 调试与性能剖析 | 定位卡顿与逻辑错 | 通用 |

> [!warning] 不要在游戏项目上花时间的技能
> 数据库、后端框架、容器化、部署运维——除非将来做联机或云存档。它们与你当前的游戏目标基本无关。

## 避坑清单

| ❌ 不要 | ✅ 应该 |
| --- | --- |
| 先搭完美框架/引擎再想玩法 | 先让 M1 能玩起来 |
| 一上来就冲 M6（聚变 + 转生） | 先做 M1 验证手感 |
| 教程地狱：只看视频不动手 | 每学一个概念就改进项目一处 |
| 到处硬编码 ID / 数值 | 坚持数据驱动（A 的 NFR-5） |
| 过早优化性能 | 1000 台机器的问题留到 M4 用批处理解决 |
| 一开始学图形学 / 自研引擎 | 用现成引擎或 DOM/CSS |

## 第一周行动清单（路线 A）

- [ ] `pnpm create vite` + TypeScript strict + ESLint/Prettier + Vitest
- [ ] 建 `sim/` 目录：固定步长 tick 循环，纯函数，配单测
- [ ] 用 JSON 定义「铁矿石 → 粉碎 → 铁粉 → 熔炉 → 铁锭」三条配方
- [ ] 实现 `BigNum`（尾数 + 指数）并补边界用例测试
- [ ] localStorage 存档 + `schemaVersion` + 迁移函数占位
- [ ] 离线结算（大步长分段模拟）+ 一个最简资源面板
- [ ] 验收标准：刷新浏览器不丢档；关掉 1 小时回来有收益

> [!tip] 达成标准
> 做到最后一条，就跨过了「会语法但不会做游戏」的分水岭。

## 学习节奏建议

- 每周固定 5–10 小时，保证**每两周至少产出一个可运行的东西**。
- 每个阶段结束做一次复盘：这一阶段真正卡住我的是什么？把它补进本笔记。
- 不追求学完，只追求**下一个里程碑能跑**。
