# 我的想法

> [!info] 概述
> 一款围绕「世界 → 区域 → 机器 → 模块」层级搭建的自动化建造游戏，核心诉求是**可存档**与**可加模组**。

## 设计目标
- 可存档
- 可加模组

## 设定

### 世界 World
- 包含于存档中
- 其下可包含多个区域

### 区域 Region
- 其下可包含多个机器
- 区域具有属性，可决定一些性质，如特定机器只能放入拥有特定属性的区域
- 矿区[^2]是一种具有特殊属性的区域

### 机器 Machine
- 安装于区域中
- 生产的最小单元
- 其下包含模块
- 主仓库[^1]是机器的一种

### 模块 Module
- 机器存储与交互的核心
- 可用于链接网络
- 可控制机器状态

例如
- 输入模块
- 输出模块
- 存储模块
- 控制模块

### 组件 Component
- 为模块或机器添加功能

---

## 网络 Net
- 用于在机器与机器之间传输资源
- 一个网络可以链接多个机器
- 存在于区域或世界中，可以存在多个
- 区域网络不能跨区域链接机器

## 资源 Resources
- 包含所有种类资源，如物品、流体、电力
- 所有资源以数据形式存储于机器的模块中

---

## 配方
- 规定配方执行条件

包含
- 原料
- 产物
- 生产时间
- 机器
- 附加条件（非必要）

配方可以为每一种原料或产物添加属性，如
- 概率产出/消耗
- 不消耗

个别机器配方可无原料或产物

## 任务链
- 用于自动执行操作
	- 合成
	- 手动搬运
- 进行复杂的多步递归手动合成
- 可少量并行，并行量取决于剩余人力

## 人力
- 存档属性（随存档保存）
- 具有上限，每次进行人工操作都需要占用一定数量人力，结束后返还人力
- 可建设机器增加人力 ~~（原始人自动化）~~

---

## 游戏流程

### 资源获取方式
- 在初始区域中建立采集站，消耗人力获取初始资源
- 建设矿区[^2]，在其中建设矿井，消耗人力获取初始资源

### 开局
- 生成一个世界，包含一个初始区域，区域中包含一个主仓库[^1]

## 字段表（草案）

### 模块 Module / 组件 Component

| 字段 | 说明 | 必填 |
|---|---|---|
| `id` | 唯一标识，命名空间格式 `modid:name` | 是 |
| `name` | 显示名 | 是 |
| `type` | 模块类型：输入 / 输出 / 存储 / 控制 | 是 |
| `tags` | 用于配方与条件匹配的标签 | 否 |
| `capacity` | 存储容量（存储模块） | 否 |
| `slots` | 可安装的组件槽位数量 | 否 |
| `netPorts` | 可连接的网络数量 / 类型 | 否 |
| `controls` | 可控制的机器状态（启停、限速等） | 否 |

| 字段 | 说明 | 必填 |
|---|---|---|
| `id` | 唯一标识，命名空间格式 `modid:name` | 是 |
| `name` | 显示名 | 是 |
| `target` | 生效对象：机器 / 模块 | 是 |
| `effects` | 效果列表（加速、增产、降耗等） | 是 |
| `stackable` | 是否可重复安装 | 否 |
| `removable` | 是否可拆卸 | 否 |
| `cost` | 安装 / 运行消耗 | 否 |

### 网络 Net

| 字段 | 说明 | 必填 |
|---|---|---|
| `id` | 唯一标识 | 是 |
| `scope` | 作用域：区域 / 世界 | 是 |
| `members` | 成员机器（含端口）列表 | 是 |
| `resourceFilter` | 允许传输的资源类型 | 否 |
| `throughput` | 吞吐量上限 | 否 |
| `capacity` | 缓冲 / 存储容量 | 否 |
| `priority` | 传输优先级 | 否 |

### 配方 Recipe

| 字段 | 说明 | 必填 |
|---|---|---|
| `id` | 唯一标识 | 是 |
| `inputs` | 原料列表：资源 + 数量 + 属性 | 否 |
| `outputs` | 产物列表：资源 + 数量 + 属性 | 否 |
| `time` | 生产时间 | 是 |
| `machine` | 适用机器（或机器标签） | 是 |
| `conditions` | 附加条件（区域属性、温度等） | 否 |
| `energy` | 能耗 | 否 |
| `unlock` | 解锁条件 / 科技 | 否 |
| `priority` | 配方冲突时的优先级 | 否 |

原料 / 产物属性：

| 属性 | 说明 |
|---|---|
| `chance` | 概率产出 / 消耗 |
| `catalyst` | 不消耗 |
| `min` / `max` | 数量范围 |

## 存档与模组

> [!warning] 优先级最高
> 这两条是设计目标里最优先的约束，建议在实现任何系统之前先把数据格式定死。

### 存档

| 项    | 方案（待定）                                   |
| ---- | ---------------------------------------- |
| 存档单位 | 一个存档 = 一个世界                              |
| 格式   | 结构化数据（JSON / 二进制），必须带 `schemaVersion`    |
| 内容   | 世界、区域、机器、模块、网络、资源、任务链、人力、进度              |
| 版本迁移 | schema 每次变更递增 `schemaVersion`，为旧版本提供迁移函数 |
| 自动保存 | 待定（定时 / 事件触发）                            |

### 模组

| 项     | 方案（待定）                                       |
| ----- | -------------------------------------------- |
| 内容注册  | 资源、机器、模块、组件、配方、区域属性全部走注册表（Registry），禁止硬编码 ID |
| ID 命名 | 统一命名空间 `<modid>:<name>`，如 `base:iron_ore`    |
| 加载顺序  | 依赖声明 + 拓扑排序                                  |
| 冲突处理  | 待定（覆盖 / 合并 / 报错）                             |
| 卸载兼容  | 存档引用了已卸载模组内容时的降级规则（占位 / 丢弃 / 拒绝加载）           |

### 数据 schema 草案

| 数据 | 标识 | 关键字段 |
|---|---|---|
| 资源 | `modid:id` | 类型（物品/流体/电力）、单位、堆叠上限 |
| 机器 | `modid:id` | 所属区域、模块槽位、组件槽位 |
| 模块 | `modid:id` | 类型、容量、连接的网络 |
| 组件 | `modid:id` | 生效目标、效果 |
| 网络 | 实例 ID | 作用域、成员机器、吞吐量 |
| 配方 | `modid:id` | 原料、产物、时间、机器、条件 |

## 未决问题

### 模块 / 组件
- [ ] 组件能否直接安装到机器上，还是只能装在模块里？
- [ ] 模块槽位 / 组件槽位是否有数量上限？
- [ ] 模块与组件能否拆卸、回收？拆卸后资源如何处理？
- [ ] 模块本身是否占用资源或空间？

### 网络
- [ ] 吞吐量 / 容量 / 损耗如何定义？
- [ ] 世界网络与区域网络的关系是什么（世界网络用于跨区域？）
- [ ] 电力是否走同一套网络，还是独立的电网系统？
- [ ] 流体 / 电力是否同样存储在模块中？

### 资源
- [ ] 存储上限、溢出规则？
- [ ] 堆叠 / 合并规则？
- [ ] 资源 ID 与注册表的最终形式（直接决定模组好不好做）？

### 配方
- [ ] 「机器」字段是硬约束还是适用列表？
- [ ] 解锁 / 科技条件如何组织？
- [ ] 循环引用与递归上限？
- [ ] 产物溢出与保底产出如何处理？

### 任务链
- [ ] 递归深度上限与死循环检测？
- [ ] 缺料 / 失败如何中断与恢复？
- [ ] 队列与优先级、取消与回滚？
- [ ] 是否随存档持久化？
- [ ] 与人力占用是否会互相冲突？

### 人力
- [ ] 上限增长曲线？
- [ ] 哪些机器可以增加人力？
- [ ] 是否随时间恢复？
- [ ] 并行时是「预占用」还是「即时消耗」？
- [ ] 人力是否是主节奏的资源闸门（直接决定核心循环手感）？

### 游戏流程
- [ ] 科技 / 进度阶梯？
- [ ] 目标与胜利条件？
- [ ] 单局时长与节奏？
- [ ] 教程与新手引导？
- [ ] 内容量估算？

### 文档 / 其他
- [ ] 「存档属性」的准确含义（随存档保存，还是属于存档层级）？
- [ ] 采集站与矿井的区别是什么？
- [ ] 实体层级图是否画入 [[游戏开发/规划/未命名.canvas]]？
