# 前端工程化

前端工程化指把「写网页」升级为**可维护、可协作、可自动化的软件工程**：用统一的工具链处理模块、编译、打包、质量检查与部署，让代码从源码稳定地产出可上线产物。

## 核心要点

- **解决三个问题**：模块化（代码怎么组织）、自动化（重复劳动交给工具）、质量保障（错误尽早暴露）。
- **工具链而非单个工具**：包管理 + 编译 + 打包 + 校验 + 测试 + 部署协同工作。
- **约定优于配置**：现代脚手架（Vite、Next.js）开箱即用，降低上手成本。

## 典型环节

| 环节 | 作用 | 常见工具 |
| ---- | ---- | -------- |
| 包管理 | 安装/锁定依赖 | npm、pnpm、yarn |
| 模块系统 | 组织代码，按需引入 | ESM、CommonJS |
| 转译/编译 | TS → JS、新语法降级 | TypeScript、Babel、esbuild |
| 打包构建 | 合并、压缩、代码分割 | Vite、Webpack、Rollup |
| 开发服务器 | 热更新（HMR）、代理接口 | Vite dev server |
| 代码质量 | 静态检查、格式化 | ESLint、Prettier |
| 测试 | 单测 / 组件测试 / E2E | Vitest、Jest、Playwright |
| 环境与部署 | 区分环境变量、产物发布 | `.env`、CI/CD、静态托管 |

## 一个项目的典型结构

```text
project/
├── src/
│   ├── main.ts        # 入口
│   ├── components/    # 组件
│   └── utils/         # 工具
├── public/            # 静态资源
├── tests/             # 测试
├── package.json
├── tsconfig.json
├── vite.config.ts
└── .env
```

这与 [[src 布局]] 的思路一致：源码与非源码分离，避免导入歧义与打包污染。

## 打包器怎么选

| 工具 | 定位 | 特点 |
| ---- | ---- | ---- |
| Vite | 开发/构建一体化 | 开发用 ESM 秒启 + HMR，生产用 Rollup 打包 |
| Webpack | 老牌全能 | 生态庞大、配置灵活，配置较复杂 |
| Rollup | 库打包 | 产物干净，适合发布 npm 包 |
| esbuild | 极速 | Go 编写，常被其他工具内置 |

## 质量与自动化

```jsonc
// package.json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc --noEmit && vite build",
    "lint": "eslint .",
    "format": "prettier --write .",
    "test": "vitest"
  }
}
```

- **提交前检查**：用 husky + lint-staged 在 `pre-commit` 跑 ESLint / Prettier。
- **持续集成**：每次推送自动跑 lint + test + build，失败即阻断合并。
- **环境变量**：以 `VITE_` 等前缀暴露给客户端，密钥类变量绝不打包进前端。
