# JSON

> 一种轻量级的数据交换格式，基于 JavaScript 对象语法，独立于编程语言，广泛用于 Web 开发、API 通信和配置文件。

---

## 核心定义

**JSON**（JavaScript Object Notation）是一种基于文本的、轻量级的数据交换格式。它采用完全独立于编程语言的文本格式来存储和表示数据，易于人阅读和编写，同时也易于机器解析和生成。

---

## 语法规范

### 基本规则
- 数据以**键值对**形式存在
- 数据之间用**逗号**分隔
- 大括号 `{}` 保存对象
- 中括号 `[]` 保存数组

### 两种数据结构

| 结构 | 说明 | 示例 |
|------|------|------|
| **对象** | 无序的键值对集合，键必须是字符串 | `{"name": "Alice", "age": 25}` |
| **数组** | 有序的值列表 | `["apple", "banana", "cherry"]` |

### 数据类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 字符串 | 必须用双引号 | `"hello"` |
| 数字 | 整数或浮点数 | `42`, `3.14` |
| 布尔值 | `true` 或 `false` | `true` |
| 空值 | `null` | `null` |
| 对象 | 嵌套对象 | `{"key": "value"}` |
| 数组 | 值的有序列表 | `[1, 2, 3]` |

> ️ **注意**：JSON 不支持 `undefined`、函数、日期对象、注释。

### 转义字符

| 转义符 | 含义 |
|--------|------|
| `\"` | 双引号 |
| `\\` | 反斜杠 |
| `\/` | 正斜杠 |
| `\b` | 退格 |
| `\f` | 换页 |
| `\n` | 换行 |
| `\r` | 回车 |
| `\t` | 制表符 |
| `\uXXXX` | Unicode 字符 |

### 各语言解析示例

**Python**

```python
import json

# 解析 JSON 字符串
json_str = '{"name": "Alice", "age": 25}'
data = json.loads(json_str)
print(data["name"])  # Alice

# 转换为 JSON 字符串
data = {"name": "Bob", "age": 30}
json_str = json.dumps(data, ensure_ascii=False, indent=2)
print(json_str)
```

**JavaScript**

```javascript
// 解析 JSON 字符串
const jsonStr = '{"name": "Alice", "age": 25}';
const data = JSON.parse(jsonStr);
console.log(data.name); // Alice

// 转换为 JSON 字符串
const data = { name: "Bob", age: 30 };
const jsonStr = JSON.stringify(data, null, 2);
console.log(jsonStr);
```

**Java**

```java
import com.google.gson.Gson;

Gson gson = new Gson();

// 解析 JSON
String jsonStr = "{\"name\": \"Alice\", \"age\": 25}";
Map data = gson.fromJson(jsonStr, Map.class);

// 转换为 JSON
Map map = new HashMap<>();
map.put("name", "Bob");
map.put("age", 30);
String jsonStr = gson.toJson(map);
```

## 应用场景

### Web API

RESTful API 最常用的数据交换格式，前后端通信的标准格式。

```http
GET /api/users/1 HTTP/1.1
Host: example.com
Accept: application/json

HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 1,
  "name": "张三",
  "email": "zhangsan@example.com"
}
```

### 配置文件

许多工具和框架使用 JSON 作为配置格式：

- `package.json`（Node.js）
- `tsconfig.json`（TypeScript）
- `launch.json`（VS Code）
- `.eslintrc.json`（ESLint）

### 数据存储

- NoSQL 数据库（如 MongoDB）以类似 JSON 的 BSON 格式存储数据
- 本地缓存和轻量级数据持久化

### 跨语言数据交换

由于 JSON 是语言无关的，不同系统之间可以通过 JSON 进行数据交换。

### 移动开发

- iOS 和 Android 应用与服务器通信
- 本地数据序列化

## 与 XML 对比

|特性|JSON|XML|
|---|---|---|
|可读性|更简洁，更接近代码|较冗长，标签嵌套多|
|解析速度|通常更快|相对较慢|
|数据大小|更小|更大（标签开销）|
|数据类型|支持基本类型|所有值都是字符串|
|注释支持|不支持|支持|
|命名空间|不支持|支持|
|适用场景|API、配置、轻量数据|文档、复杂结构、SOAP|

## 注意事项

### 常见陷阱

1. **键必须用双引号**
    
    ```json
    //  错误
    { name: "Alice" }
    
    //  正确
    { "name": "Alice" }
    ```
    
2. **不支持尾随逗号**
    
    ```json
    //  错误
    { "a": 1, "b": 2, }
    
    //  正确
    { "a": 1, "b": 2 }
    ```
    
3. **不支持注释**
    
    ```json
    //  错误 - JSON 不允许注释
    {
      "name": "Alice" // 这是名字
    }
    ```
    
4. **日期需要特殊处理**
    
    ```json
    // JSON 没有原生日期类型，通常用字符串
    { "createdAt": "2024-01-15T08:30:00Z" }
    ```
    
5. **大数精度问题**
    
    ```json
    // 超过 JavaScript Number 安全范围的整数可能丢失精度
    { "id": 9007199254740993 }
    ```
    

### 最佳实践

- 使用 `UTF-8` 编码
- 键名使用 `camelCase` 或 `snake_case` 保持一致
- 避免过深的嵌套（建议不超过 3-4 层）
- API 响应保持统一结构
- 敏感数据不要明文存储在 JSON 中

## 相关扩展格式

|格式|说明|
|---|---|
|**JSON5**|允许注释、尾随逗号、单引号等，更宽松|
|**JSONC**|支持注释的 JSON，VS Code 配置使用|
|**JSONL / NDJSON**|每行一个 JSON 对象，适合流式处理|
|**BSON**|二进制 JSON，MongoDB 使用|
|**MessagePack**|二进制序列化格式，比 JSON 更紧凑|
|**JSON Schema**|用于验证 JSON 数据结构|
|**JSONPath**|类似 XPath，用于查询 JSON 数据|

## 历史背景

- **2001 年**：Douglas Crockford 首次提出并推广 JSON 格式
- **2005 年**：JSON 开始在 AJAX 编程中广泛使用
- **2006 年**：json.org 网站上线，JSON 社区快速发展
- **2013 年**：ECMA-404 标准发布，JSON 成为国际标准
- **2017 年**：RFC 8259 发布，取代早期的 RFC 7159
- **2020 年代**：JSON 成为 Web API 事实上的标准数据格式
