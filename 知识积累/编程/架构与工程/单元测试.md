# 单元测试

单元测试针对最小的可测试单元（通常是一个函数或类）验证行为是否符合预期。对数值密集的模拟类项目，它是**防止改一处崩一片**的关键保障，`学习规划` 称其为「数值密集项目的命脉」。

## 核心要点

- **快速、隔离、可重复**：不依赖网络、数据库、真实时间与随机。
- **回归网**：重构或调数值后立刻知道有没有破坏既有行为。
- **既是文档也是设计压力**：难测往往意味着耦合太高。
- **金字塔**：单元测试最多，集成次之，端到端最少。

## AAA 结构

```typescript
it("离线 1 小时应结算持续产出", () => {
  // Arrange 准备
  const state = makeState({ ironPerSec: 2 });
  // Act 执行
  const gained = settleOffline(state, 3600);
  // Assert 断言
  expect(gained.iron).toBe(7200);
});
```

## 好测试的特征

| 特征 | 说明 |
| ---- | ---- |
| 单一职责 | 一个用例只验证一个行为 |
| 独立 | 用例之间无顺序依赖，可任意单跑 |
| 描述性命名 | 一眼看懂「输入 → 期望」 |
| 稳定 | 不因时间、随机、并发而偶发失败 |
| 快 | 毫秒级，才能频繁运行 |

## 覆盖率

- 覆盖率是**参考**不是目标；核心逻辑（模拟、序列化、迁移）应重点覆盖。
- 边界优先：`0`、负数、极大数、空输入、跨天/跨段结算。
- 不要为了凑覆盖率测试 getter/setter 之类的琐碎代码。
