# 容器

容器（Container）是一种**轻量级的应用打包与隔离技术**：把应用及其依赖（库、配置、运行时）一起封装成标准化单元，从而做到「一次构建，处处运行」。它解决了「在我机器上能跑」的环境一致性问题，是 [[../教程/python/Python进阶阶段学习规划表]] 中 4.2 节「容器化与部署」的核心，也是现代后端交付的基础设施。

## 核心要点

- **本质**：容器是宿主机上被隔离的进程，共享宿主机的操作系统内核，因此比虚拟机更轻、启动更快。
- **三大核心概念**：**镜像（Image）** 是只读模板，**容器（Container）** 是镜像的运行实例，**仓库（Registry）** 用来分发镜像。
- **不可变交付**：镜像一旦构建就固定不变，环境差异在构建期解决，而不是部署期。
- **Docker 是最流行的实现**，但容器是标准（OCI），还有 Podman、containerd 等运行时。
- ⚠️ **概念区分**：这里的「容器」指操作系统级虚拟化；[[控制反转]] / [[依赖注入]] 里的「IoC 容器」是对象管理组件，两者只是同名，不要混淆。

## 详细说明

### 容器 vs 虚拟机

| 维度 | 容器 | 虚拟机（VM） |
| ---- | ---- | ------------ |
| 隔离级别 | 进程级，共享宿主内核 | 硬件级，各自完整 OS |
| 启动速度 | 秒级甚至毫秒级 | 分钟级 |
| 资源占用 | 小，仅打包应用与依赖 | 大，含完整操作系统 |
| 隔离强度 | 较弱（内核共享） | 强（硬件虚拟化） |
| 典型工具 | Docker、Podman、containerd | VMware、VirtualBox、KVM |

### 核心概念

| 概念 | 说明 |
| ---- | ---- |
| 镜像 Image | 只读模板，由多层（Layer）叠加而成，层可复用和缓存 |
| 容器 Container | 镜像的可运行实例，可创建、启动、停止、删除 |
| 仓库 Registry | 存放与分发镜像，如 Docker Hub、私有 Harbor |
| Dockerfile | 定义镜像构建步骤的文本文件 |
| 卷 Volume | 持久化数据，独立于容器生命周期存在 |
| 网络 Network | 容器间及容器与外部通信的虚拟网络 |

> [!note]
> 镜像分层是构建缓存的关键：Dockerfile 中不常变动的指令写在前面，频繁变动的写在后面，能显著加快重复构建。

### 常用命令

```bash
docker pull nginx:latest          # 拉取镜像
docker images                     # 列出本地镜像
docker run -d -p 8080:80 nginx    # 后台运行并做端口映射
docker ps                         # 查看运行中的容器（-a 含已停止）
docker exec -it <容器ID> bash     # 进入容器内部
docker logs -f <容器ID>           # 跟踪日志
docker stop <容器ID>              # 停止容器
docker rm <容器ID>                # 删除容器
docker rmi <镜像ID>               # 删除镜像

docker build -t myapp:1.0 .       # 根据 Dockerfile 构建镜像
docker push myapp:1.0             # 推送到仓库
```

### Dockerfile 示例

以 [[FastAPI]] 或 [[Flask]] 服务为例：

```dockerfile
FROM python:3.12-slim

WORKDIR /app

# 先复制依赖清单，利用构建缓存
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

要点：

- 用 `slim`/`alpine` 基础镜像减小体积。
- 依赖清单先复制，改动源码时不必重装依赖。
- 用 `.dockerignore` 排除 `.git`、`__pycache__`、`.env` 等不该进镜像的内容。
- 生产镜像避免用 `latest` 标签，应使用明确版本号。

### Docker Compose：多容器编排

单个应用往往依赖数据库、缓存等，Compose 用一个 YAML 描述整个环境：

```yaml
services:
  api:
    build: .
    ports:
      - "8000:8000"
    depends_on:
      - db
    environment:
      - DATABASE_URL=mysql://user:pass@db:3306/mydb
  db:
    image: mysql:8
    environment:
      - MYSQL_ROOT_PASSWORD=pass
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
```

```bash
docker compose up -d     # 一键启动全部服务
docker compose down      # 停止并移除
docker compose logs -f   # 查看日志
```

### 数据与网络

- **数据持久化**：容器删除后内部文件随之消失，需要持久化的数据必须挂载卷（named volume）或绑定宿主机目录（bind mount）。
- **网络**：同一 Compose 网络内，服务可用**服务名**互相访问（如上面 `db`）。对外暴露用端口映射 `-p 宿主机端口:容器端口`。
- **配置注入**：敏感信息通过环境变量或 Secret 注入，不要硬编码进镜像，和 [[../教程/python/用 Python 搭建复杂项目]] 中的配置管理原则一致。

### 从 Compose 到 Kubernetes

当服务数量、副本和发布频率上升，就需要容器编排：

| 层次 | 工具 | 适用场景 |
| ---- | ---- | -------- |
| 单机单容器 | `docker run` | 本地开发、简单服务 |
| 单机多容器 | Docker Compose | 开发环境、小型部署 |
| 集群编排 | Kubernetes（K8s） | 生产环境、弹性伸缩、自愈 |

K8s 的核心对象包括 Pod、Deployment、Service、Ingress 等，负责调度、扩缩容、滚动更新和故障自愈。它是进阶方向，入门阶段先掌握 Docker 与 Compose 即可。

### 容器化带来的收益

- **环境一致**：开发、测试、生产使用同一镜像，消除环境漂移。
- **快速交付**：镜像可秒级启动，方便扩缩容与回滚。
- **隔离与资源限制**：通过 `--memory`、`--cpus` 限制资源，互不干扰。
- **与 CI/CD 结合**：流水线中构建镜像、跑测试、推送仓库一气呵成，参见 [[单元测试]] 与 [[Git]]。

> [!warning] 安全提醒
> - 容器默认以 root 运行，尽量使用非 root 用户（`USER` 指令）。
> - 不要把密钥、密码打进镜像层，即使是删除也可能残留在历史层中。
> - 定期更新基础镜像，修复已知漏洞。
