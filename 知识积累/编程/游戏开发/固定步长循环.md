# 固定步长循环

固定步长循环（fixed timestep）让模拟始终以**恒定的时间步长**推进，而不是跟着渲染帧率变化。它解决了「帧率高时快、帧率低时慢」以及「离线结算与实时结算结果不一致」的问题，是 `学习规划` 阶段 1 的第一个自测项。

## 为什么需要

如果每帧直接乘 `deltaTime`（可变步长）：

- 掉帧时步长变大，数值误差累积，可能**漂移**；
- 不同设备帧率不同，模拟结果不可复现；
- 离线结算用「一帧」还是「很多帧」结果对不上。

固定步长把「模拟」与「渲染」解耦：模拟以固定 `dt` 推进，渲染只负责显示。

## 累加器模式

```typescript
const FIXED_DT = 1 / 60; // 模拟步长，秒
let accumulator = 0;

function frame(now: number) {
  let frameTime = (now - lastTime) / 1000;
  lastTime = now;
  frameTime = Math.min(frameTime, 0.25); // 防止切后台后一次性追帧爆炸

  accumulator += frameTime;
  while (accumulator >= FIXED_DT) {
    update(FIXED_DT); // 纯逻辑，固定步长
    accumulator -= FIXED_DT;
  }

  render(accumulator / FIXED_DT); // 可选：插值，让画面平滑
  requestAnimationFrame(frame);
}
```

## 关键要点

| 要点 | 说明 |
| ---- | ---- |
| 逻辑纯函数 | `update(dt)` 不碰 DOM，便于单测（见 [[单元测试]]） |
| 限制追帧上限 | 切后台/断点后 `frameTime` 可能巨大，必须 clamp |
| 大数运算 | 放置游戏数值会暴涨，配合 [[大数（BigNum）]] |
| 离线结算 | 用同一 `update(dt)` 分大步长循环，保证与在线一致 |
| 插值渲染 | 用累加器余数插值，避免低帧率下画面抖动 |

## 与离线结算的关系

离线 8 小时不必真跑 8×3600 次 `update`，可切成少量大 `dt` 分段推进；只要所有收益都是线性/可合并的，结果就与在线一致。若存在非线性（如随机事件），需要分段近似并记录误差。
