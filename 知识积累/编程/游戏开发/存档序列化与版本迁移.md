# 存档序列化与版本迁移

存档序列化是把运行状态转成可持久化的数据（如 [[JSON]]），版本迁移则保证**旧存档在代码升级后仍能读入、不损坏**。`学习规划` 把它列为路线 A 的验收标准（AC-8、FR-15.2）：刷新不丢档、旧档能升级。

## 核心要点

- **存档带 `schemaVersion`**：每个存档显式标注版本，代码据此选择迁移路径。
- **迁移是函数链**：`v1 → v2 → v3`，每步只负责相邻版本的转换。
- **默认值兜底**：新增字段给默认值，缺失字段不应导致崩溃。
- **序列化只存状态**：不存派生数据（如缓存、UI 中间量），减少迁移面。
- **备份与校验**：迁移前保留原档，失败可回退。

## 存档结构

```json
{
  "schemaVersion": 3,
  "savedAt": 1750000000000,
  "resources": { "iron": { "mantissa": 1.2, "exponent": 5 } },
  "machines": [{ "id": "smelter", "count": 4 }]
}
```

## 迁移实现

```typescript
type Save = { schemaVersion: number } & Record<string, unknown>;
type Migration = (save: Save) => Save;

const migrations: Record<number, Migration> = {
  1: (s) => ({ ...s, schemaVersion: 2, machines: [] }),
  2: (s) => ({ ...s, schemaVersion: 3, prestige: 0 }),
};

function migrate(save: Save): Save {
  let cur = save;
  while (cur.schemaVersion < CURRENT_VERSION) {
    const step = migrations[cur.schemaVersion];
    if (!step) throw new Error(`缺少迁移: v${cur.schemaVersion}`);
    cur = step(cur);
  }
  return cur;
}
```

## localStorage 读写

```typescript
const KEY = "idle-save";

function saveGame(state: State) {
  localStorage.setItem(KEY, JSON.stringify(serialize(state)));
}

function loadGame(): State | null {
  const raw = localStorage.getItem(KEY);
  if (!raw) return null;
  const parsed = JSON.parse(raw) as Save;
  return deserialize(migrate(parsed));
}
```

## 测试与容错

- 为每个版本准备**样例存档**，断言迁移后结果符合预期（见 [[单元测试]]）。
- 处理损坏/空档：`try/catch` 后给出「新游戏或恢复备份」选项，不要直接白屏。
- 大数用 [[大数（BigNum）]] 的对象形式存储，避免字符串精度问题。
- 迁移函数保持纯函数，便于单测与回放。
