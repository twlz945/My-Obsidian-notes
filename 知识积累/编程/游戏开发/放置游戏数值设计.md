# 放置游戏数值设计

放置（增量）游戏的核心乐趣来自「增长曲线」：玩家用越来越大的投入换取越来越快的产出。数值设计决定成长是**爽快**还是**卡死**，`学习规划` 推荐以 GDC《The Math of Idle Games》为必读。

## 核心要点

- **产出随投入增长**：机器/升级让单位时间产出提升，形成正反馈。
- **成本递增**：购买越多越贵，制造「攒钱—购买—再攒钱」的节奏。
- **数量级增长**：后期数值跨越多个数量级，需 [[大数（BigNum）]] 支撑。
- **重置换永久增益**：转生（prestige）用重置换长期倍率，延长生命周期。

## 常见增长曲线

| 曲线 | 公式 | 特点 |
| ---- | ---- | ---- |
| 线性 | `cost = a·n` | 简单，后期乏力 |
| 多项式 | `cost = a·n^k` | 最常用，节奏可控 |
| 指数 | `cost = a·r^n` | 增长猛烈，需强产出匹配 |
| 双指数 | `a^(b^n)` | 极限数值，慎用 |

购买成本常用 `cost = base × growth^n`（`growth` 取 `1.07`~`1.15` 之间微调手感）。

## 关键公式示例

```typescript
// 第 n 台机器的成本
function cost(base: number, growth: number, n: number): BigNum {
  return new BigNum(base, 0).mul(new BigNum(growth, 0).pow(n));
}

// 总产出 = Σ(数量 × 单产 × 全局倍率)
function production(state: State): BigNum {
  let total = new BigNum(0, 0);
  for (const m of state.machines) {
    total = total.add(m.count.times(m.baseOutput));
  }
  return total.times(state.globalMultiplier);
}
```

## 调参原则

- **前期快、中期稳、后期靠机制**：前 10 分钟必须不断有正反馈。
- **每次购买要有意义**：成本增长率与产出增长率要匹配，避免「买了没用」。
- **离线收益**：给一个上限或打折系数，防止长期离线破坏平衡。
- **可视化**：进度条、预估到达时间（ETA）比裸数字更耐玩。
- **数据外置**：所有参数放数据表，配合 [[数据驱动设计]] 快速迭代。
