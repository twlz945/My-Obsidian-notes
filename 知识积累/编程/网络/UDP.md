# UDP（用户数据报协议）

**UDP**（User Datagram Protocol）是 TCP/IP 协议栈中的**传输层协议**，协议号为 17，由 RFC 768 定义。它采用**无连接、面向数据报、尽最大努力交付**的传输方式，核心设计目标是低开销和低延迟。

---

## 核心特性

|特性|说明|
|---|---|
|**无连接**|发送数据前无需建立连接，直接封装发送|
|**面向数据报**|保留应用层消息边界，不拆分不合并报文|
|**不可靠传输**|无确认、重传、排序机制，可能丢包、乱序、重复|
|**无流量/拥塞控制**|不根据网络状况调整发送速率|
|**支持广播/多播**|天然支持一对一、一对多、多对多通信|
|**首部开销小**|固定 8 字节，远低于 TCP 的至少 20 字节|

---

## UDP 报文头部

UDP 头部固定为 **8 字节**，包含四个 16 位字段：

```
 0      7 8     15 16    23 24    31
+--------+--------+--------+--------+
| 源端口  | 目的端口 |
+--------+--------+--------+--------+
|   长度   |  校验和  |
+--------+--------+--------+--------+
|           数据（可选）              |
+-----------------------------------+
```

|字段|说明|
|---|---|
|**源端口**|发送方端口，可选|
|**目的端口**|接收方端口，必选|
|**长度**|UDP 头部 + 数据总长度，最小 8 字节|
|**校验和**|检测传输错误，可选|

---

## UDP 与 TCP 对比

|维度|UDP|TCP|
|---|---|---|
|连接方式|无连接|面向连接（三次握手）|
|可靠性|不保证|可靠传输（确认+重传）|
|传输形式|数据报（保留边界）|字节流（无边界，有粘包问题）|
|顺序保证|不保证|有序到达|
|流量/拥塞控制|无|有|
|首部开销|8 字节|最小 20 字节|
|通信模式|一对一、一对多、多对多|仅点对点|
|延迟|低|相对较高|

## 典型应用场景

|场景|说明|
|---|---|
|**DNS 查询**|端口 53，快速请求-响应|
|**实时音视频**|VoIP、视频会议、直播推流，容忍少量丢包|
|**在线游戏**|实时位置同步，低延迟优先|
|**DHCP**|端口 67/68，动态 IP 分配|
|**NTP**|端口 123，网络时间同步|
|**SNMP**|端口 161/162，网络管理|
|**TFTP**|端口 69，简单文件传输|
|**广播/多播**|局域网设备发现、批量推送|

## 编程示例（Python）

### UDP 服务端

```python
import socket

server = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
server.bind(("127.0.0.1", 9999))
print("UDP 服务端已启动，监听端口 9999")

while True:
    data, addr = server.recvfrom(4096)
    print(f"收到来自 {addr} 的数据: {data.decode()}")
    server.sendto(b"ack: " + data, addr)
```

### UDP 客户端

```python
import socket

client = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
client.settimeout(2)  # 设置超时，避免无限等待

client.sendto(b"Hello UDP", ("127.0.0.1", 9999))

try:
    data, server = client.recvfrom(4096)
    print(f"收到服务端响应: {data.decode()}")
except socket.timeout:
    print("未收到响应，可能丢包")

client.close()
```

## 注意事项

- **不保证送达**：数据包可能丢失、乱序或重复，应用层需自行处理
- **建议设置超时**：UDP 客户端应设置 `settimeout()`，避免阻塞等待永远不会到达的响应
- **无拥塞控制**：高速发送可能导致网络拥塞和丢包，应用层需控制发送速率
- **适合小数据量**：单次报文不宜过大，需考虑 MTU 限制，避免 IP 分片
- **广播/多播需配置**：发送广播数据需设置 `SO_BROADCAST` 选项
- **可靠传输需自建**：若需要可靠性，可在应用层实现确认、重传、排序等机制（如 QUIC 协议就是在 UDP 之上实现了可靠传输）

---

## 简要总结

UDP 的核心价值在于**简单、快速、低延迟**，适合对实时性要求高、能容忍少量数据丢失的场景。它不建立连接、不保证可靠、不控制拥塞，但正因如此，它比 TCP 更轻量，在 DNS、实时音视频、在线游戏、广播通信等领域不可替代。
